# Segurança de rede de saída na v0.8.7

## Objetivo

As integrações externas continuam opcionais e desligadas por padrão. Quando habilitadas, uma URL só
é utilizada depois de normalização estrita, policy por provider e validação de todos os endereços
resolvidos. O transporte conecta ao IP já aprovado; não faz uma segunda resolução de DNS entre a
validação e a conexão.

## Policies

| Provider | Destino permitido | Credencial | Observações |
| --- | --- | --- | --- |
| OpenAI | host oficial HTTPS, porta 443 e path de API esperado | enviada somente ao host oficial | `base_url` arbitrária é recusada |
| Gemini | host oficial HTTPS, porta 443 e path esperado | escopo exclusivo do host oficial | nenhuma credencial em redirect |
| Ollama | loopback explícito, somente em ambiente local | sem segredo externo | recusado fora de `local`/`development`/`test` |
| fonte RAG HTTP | host presente na allowlist configurada e HTTPS | nenhuma por padrão | conteúdo educacional, tamanho limitado |

Normalização rejeita userinfo, fragmento, hostname ambíguo, porta não permitida, IPv4 em notações
alternativas, IPv4 embutido em IPv6, endereço não global e hostname fora da allowlist. Todos os
resultados A/AAAA precisam ser aceitáveis; um único endereço privado/reservado invalida o destino.

## Transporte fixado

`PinnedHTTPSTransport` abre a conexão para o endereço validado e preserva o hostname original apenas
para `Host` e SNI/verificação TLS. Proxy de ambiente e redirects ficam desabilitados. O cliente aplica
limites de conexão/leitura, número máximo de bytes e `Content-Type` esperado. Resposta que excede o
limite é interrompida e não entra no índice nem no contexto de IA.

Isso fecha o TOCTOU de resolução dentro do processo, mas não substitui controles de implantação:

- firewall/proxy de egress com deny-by-default;
- DNS confiável e telemetria de consultas;
- CA bundle e relógio do host atualizados;
- secret manager e rotação de credenciais;
- alertas para volume, destino ou latência anormais.

## Redirections e credenciais

Redirect HTTP é recusado, não revalidado automaticamente. A aplicação não copia `Authorization`, API
key ou query secret para host alternativo. Chaves nunca entram em payload de resposta, auditoria ou
log e não são persistidas no browser.

## Evidência automatizada

Os testes de `safe_url`, transporte e providers cobrem DNS rebinding, conjunto misto de IPs,
loopback/privado/link-local/multicast, IPv4 alternativo, userinfo, portas, redirects, Host/SNI,
limites de resposta e escopo de credencial. O threat model registra firewall de egress como risco
residual; não há claim de pentest ou validação de infraestrutura.
