# Prescripta v1.1.0 — Assurance Audit Fixes

Prescripta v1.1.0 ships the corrections from the November 2026 assurance audit of v1.0.0: clinical
decision consistency, authorization on PostgreSQL, CDS contract honesty, session revocation,
dependency and image security, and stronger evidence (real-concurrency and full-PostgreSQL tests).
It is published as a **pre-release**: the planned dogfood runs of Derivanta Engine and Assertiva
were blocked by tool permissions in the audit environment and are still pending.

Full findings, evidence and negative controls:
[`docs/audits/2026-11-prescripta-assurance/`](../audits/2026-11-prescripta-assurance/README.md).

## Fixed

- **Patient listing on PostgreSQL** returned HTTP 500 for clinicians: the scope query used a JSON
  `LIKE` that PostgreSQL rejects (and that matched capability substrings on SQLite). Scope and
  per-object checks now share exact JSON-array membership on both dialects.
- **Age-related risk** was dropped by the decision orchestrator and could *decrease* when an
  elderly-caution finding was added. One monotonic composition is shared by every path; age alone
  is capped at `alto` and never blocks (ADR 010, pending clinical review).
- **CDS API:** ambiguous presentations fail closed (`409 ambiguous_medication` with candidates);
  observations are reported as not evaluated and prevent a favorable decision; concurrent requests
  with the same `Idempotency-Key` replay or return 409 instead of 500 with an orphan audit row.
- **Alternatives** were screened by the base engine alone, with the original drug's dose, could be
  shown as `liberado`, and grouped unrelated drugs through a placeholder class. They are now review
  candidates screened by the shared orchestrator without inherited dose (ADR 011).
- **Dose display:** no scientific notation in alert texts and no rounding of small doses on screen;
  a concentration × volume dose declares the missing concentration ceiling as not evaluated.
- **Sessions:** logout revokes the presented token server-side; browser races between page load,
  logout and login fixed; logout propagates across tabs.
- **Configuration:** one definition of local environments; non-local environments reject JWT
  secrets shorter than 32 bytes and the placeholders published in the repository.
- Audit search treats `%`/`_` literally; alternatives scan the whole catalog.

## Security and supply chain

- Python lock updated (Dependabot #67): pip-audit 24 records → 0. npm (Dependabot #65 plus a
  non-breaking audit fix): 6 high → 0. GitHub Actions bumped by verified SHA (Dependabot #66).
- Expired CVE-2026-14456 exception removed after moving the backend runtime to a patched distroless
  digest; nginx runtime 1.30.4 → 1.30.6 (34 HIGH/CRITICAL → 0).
- One temporary, exact-PURL exception for two zlib `gz*` advisories, **expiring 2026-11-22**
  (`docs/security/accepted-risks.md`); release evidence now derives exceptions from the policy file
  and refuses expired ones.
- Pull-request secret scanning fixed; weekly scheduled container scan added.

## Upgrade notes

- Run migrations: `b11a2c3d4e50` (revoked tokens) and `c12b3d4e5f60` (patient institution index).
- Existing sessions must log in again (tokens now require a `jti`).
- Non-local deployments must set `PRESCRIPTA_SECRET_KEY` to at least 32 bytes.
- OpenAPI: additive only (`observations_evaluation`; new alternative fields in an untyped list).

## Known limits

- Derivanta Engine and Assertiva were not executed against this release (permission blocked);
  quality evidence comes from the project's own tests and gates.
- Clinical rules remain demonstrative; the age ceiling and the absence of concentration ceilings
  require specialist review. Dependabot alerts/security updates are disabled at repository level.

## Safety boundary

Only synthetic or demonstration data is supported. Deterministic backend services calculate; AI
outputs remain proposals or explanations; authorized humans approve. No clinical, regulatory,
complete FHIR/CDS Hooks or complete OMOP conformance is claimed.
