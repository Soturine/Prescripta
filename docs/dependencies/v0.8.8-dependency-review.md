# Revisão de dependências da v0.8.8

Revisão executada em 8 de agosto de 2026 sobre a `main` real. Os PRs #26 e #28–#33 foram
inspecionados como sinais; nenhum foi mesclado, usado como branch-base ou cherry-picked. As
alterações aceitas foram reproduzidas em commits próprios e os PRs serão comentados e encerrados
após a publicação da v0.8.8.

## Backend

O grupo foi aplicado por componentes compatíveis, mantendo o parser HTTP padrão do Uvicorn. O
parser experimental `zttp` não foi instalado nem habilitado. Startup ASGI real, HTTP, cookies,
proxy/security controls, Windows, outbound HTTP e AI Task Router integram a suíte obrigatória.

O SDK OpenAI continua atrás de `SafeOutboundHTTPClient`, allowlist, timeout, configuração
administrativa, Task Router e provenance. A atualização não cria caminho direto entre LLM e banco.

`pydantic` permanece em 2.13.4 com `pydantic-core` 2.46.4. O candidato 2.47.0 foi
`deferred_with_blocker`, pois Pydantic declara dependência exata no core 2.46.4. Retomar somente
quando uma versão estável de Pydantic declarar oficialmente o novo par, seguida de validação de
schemas, serialização, OpenAPI e migrations.

## Frontend e advisories

Axios 1.19.0 foi priorizado porque eleva `form-data` para `^4.0.6`, evitando fresh installs no
intervalo afetado por CRLF. Os patches transitivos elevaram `brace-expansion` para 5.0.9 e `nanoid`
para 3.3.18. `npm audit` retorna zero vulnerabilidades.

O advisory `GHSA-qwww-vcr4-c8h2` foi atualizado oficialmente em 7 de agosto de 2026 e agora lista
React Router 7.18.2 como versão corrigida. Essa é a versão exata instalada. A exceção temporária,
que venceria em 15 de agosto, foi removida do gate e de `accepted-risks.md`; qualquer novo
high/critical volta a falhar sem allowlist.

## Supply chain

- não foi adicionada dependência direta nova para Research/RWE; foram reutilizados Python,
  SQLAlchemy, Pydantic, React e os componentes existentes;
- licenças dos updates permanecem compatíveis: MIT/BSD/Apache-2.0 conforme o pacote já aprovado;
- os pacotes publicados consumidos não executam install scripts na instalação do Prescripta;
- lockfiles são a fonte reproduzível de CI; `npm ci` e `pip install -r requirements-dev.txt` são os
  caminhos validados;
- SBOM backend/frontend deve ser gerado da árvore instalada e validado antes de ser anexado à
  Release.
