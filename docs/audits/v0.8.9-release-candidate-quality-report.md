# Relatório de qualidade do release candidate v0.8.9

Este documento registra a validação pré-release do conteúdo candidato. O commit que inclui o
relatório não tenta conter o próprio SHA; a evidência autoritativa do SHA final são os workflows do
GitHub executados após o push, antes da tag.

## Escopo do candidato

- baseline: `abb9ad82aed863a887011ffd9866ba1d283e495f` (`v0.8.8`);
- branch: `main`;
- runtime local: Windows, Python 3.12.6, Node 24.11.1, npm 11.6.2 e Docker 28.5.1;
- dados: somente fixtures sintéticas, IA externa desativada;
- estratégia: testes focados durante implementação e uma execução completa no RC.

| dependências locais | `pip-audit` sem vulnerabilidades; npm sem HIGH/CRITICAL e sem exceção ativa |
| repositório | texto, links, assets, versão, i18n, install scripts e diff verdes |

O primeiro comando E2E completo expôs seletores que ainda esperavam os rótulos anteriores do menu e
foi encerrado pelo timeout externo depois de registrar cinco falhas equivalentes. Os seletores foram
atualizados; uma expectativa de enum bruto em auditoria e outra de detalhe técnico aberto foram
substituídas pelos contratos novos. A revalidação segmentada cobriu todos os 19 cenários únicos sem
repetir a matriz inteira.

O primeiro build final de container foi interrompido por `ECONNRESET` do registry durante `npm ci`,
antes de iniciar a stack. O Dockerfile recebeu cache npm BuildKit e retries limitados; a imagem foi
construída e o smoke completo passou. Não houve suppressão de erro de dependência ou de scan.

## Segurança, dependências e publicação

Resultados remotos de CodeQL, audits, gitleaks, SBOM, Container e attestations são vinculados ao SHA
final no relatório ao usuário e na GitHub Release. Isso evita registrar como verde um workflow que
ainda não executou ou criar um commit pós-tag apenas para inserir seu próprio identificador.

Na primeira execução remota do candidato, o Gitleaks apontou `pharmacy-v089-scope-001`, uma nova
fixture sintética distinta de `break-uow-v088`. Como o finding não correspondia ao fingerprint já
revisado da v0.8.8, `.gitleaksignore` permaneceu inalterado e a fixture foi substituída por um valor de
teste de baixa entropia. O scan Container também encontrou 23 vulnerabilidades HIGH/CRITICAL sem
correção publicada na base Debian do backend, e não nas dependências da aplicação. A base foi trocada
pela variante oficial Python 3.12.13 Alpine fixada por digest; smoke completo e Trivy 0.70.0 locais
confirmaram funcionamento non-root e zero findings HIGH/CRITICAL antes da nova execução remota.

## Limitações

usabilidade humana, pentest ou certificação de deployment. Veja a
