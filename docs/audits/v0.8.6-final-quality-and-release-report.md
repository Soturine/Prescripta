## Security scans e supply chain

O gate local executa `pip check`, `pip-audit` sobre o lock de runtime, audit npm com allowlist temporal
estrita e geração de SBOM CycloneDX backend/frontend. O GitHub Actions executa ainda CodeQL para Python
e JavaScript/TypeScript e gitleaks com histórico completo.

Há um único risco npm temporariamente aceito, restrito ao advisory `GHSA-qwww-vcr4-c8h2` do React
Router em uma SPA sem RSC/Server Actions, com expiração automática em **15/08/2026**. Qualquer novo
high/critical ou a expiração bloqueia o workflow. Isso não declara a dependência genericamente segura.

Resultados locais: `pip-audit` não encontrou vulnerabilidade conhecida no lock de runtime; o checker
npm não encontrou high/critical inesperado e validou somente a exceção temporária documentada. SBOMs
CycloneDX foram gerados com sucesso:

```text
fd3c8fb62e73069ff7db73ba0f3a7a4d67c8f1e40cee4cf8ecdeae8860578bec  .tmp/sbom-backend.json
82c85d4ceb4200a484ffa4d56743a3c367a3150fe77fe8c95d6bad079aa52da6  .tmp/sbom-frontend.json
```

Esses hashes identificam a geração local; os SBOMs oficiais do workflow são artifacts próprios da
execução remota. A evidência remota válida para CodeQL e gitleaks é a execução `success` cujo `headSha`
seja exatamente o commit dereferenciado pela tag; qualquer outro resultado bloqueia a publicação.

O primeiro candidato remoto (`1e3780f`, CI `30425963711`, Security `30425963714`) foi corretamente
rejeitado: havia um SHA inválido de `actions/setup-node` e o check de whitespace usava checkout raso
demais para comparar apenas o commit. O pin foi resolvido contra a tag oficial `v4.4.0` e o job de
qualidade passou a buscar dois commits. Esse candidato não recebeu tag.

## Limitações e validações externas pendentes

- Não houve validação clínica de rulesets, doses, recomendações, usability/human factors ou efetividade
  por especialistas independentes.
- Não houve QMS, clinical safety officer, comitê institucional, piloto, monitoramento pós-implantação,
  análise jurídica/LGPD ou enquadramento/regularização Anvisa.
- Não houve pentest/DAST independente, avaliação formal de BOLA em toda superfície, DLP, egress firewall,
  WORM, secret manager, OIDC/BFF, observabilidade ou teste de disaster recovery institucional.
- FHIR/SMART/CDS Hooks são somente referências; adapters atuais são compatibilidade parcial demo.
- Terminologia/catálogo/fatos clínicos legados não foram migrados completamente; não existe servidor
  terminológico oficial.
- Busca lexical não foi validada quanto a recall, precision, groundedness, poisoning ou drift.
- Branch protection/ruleset depende de estado externo do GitHub e não é provado pelo código.
- O sistema continua exclusivamente demonstrativo/educacional e deve usar apenas dados fictícios.

## Critério de publicação

A tag só pode ser criada se: worktree limpo, `origin/main` igual ao SHA local, CI obrigatório do SHA
final verde, tag inexistente, migration/gates locais aprovados e release histórica `v8.6.0` preservada
com aviso transparente. Falha ou ausência de qualquer evidência bloqueia tag e release.
