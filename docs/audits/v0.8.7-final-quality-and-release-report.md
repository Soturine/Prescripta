## PostgreSQL e migrations

Um PostgreSQL 17 Alpine descartável foi executado localmente. A primeira rodada detectou, por
`alembic check`, uma unicidade redundante em `patient_psychological_contexts.patient_id`: a migration
criava constraint e índice unique, enquanto o model declara o índice. A migration ainda não publicada
foi corrigida para manter somente o índice unique canônico.

Depois da correção, `downgrade base → upgrade head → alembic check` passou com “No new upgrade
operations detected”. O CI repete `upgrade head → downgrade base → upgrade head → check` em
PostgreSQL 17. Head esperado: `b87a224c617e`.

## Evidência funcional e adversarial

- concentração × volume e quantidades decimais preservam dimensão; volume duplicado divergente
  abstém; dose extrema não retorna verde;
- taxa contínua e PRN exigem campos próprios;
- mesmo tenant sem relação e cross-tenant listam zero e não leem objeto;
- break-glass real exige motivo/purpose/capability e é encerrado/auditado;
- override real recusa auto-revisão, aceita segundo médico independente e registra evento;
- DNS rebinding, conjunto misto de IPs, redirects, ports/encodings e credencial fora do host são
  recusados;
- sessão 401, falha 503, retry e vazio mantêm estados diferentes no browser.

## Assets e documentação

O capturador inicia backend/frontend com banco temporário, espera readiness, autentica por cookie
HttpOnly, usa motion reduzido e fontes prontas, recusa erros inesperados do navegador, gera GIF via
`ffmpeg`, escreve manifesto e substitui `docs/assets/current` atomicamente. Todos os dados e e-mails
são do domínio fictício `prescripta.local`.

README, changelog, release notes, threat model, hazard log, autorização, egress, dependências,
operações, UX e matriz de fechamento foram atualizados. O README aponta para índice genérico de
releases e não funciona como changelog.

## Riscos e blockers mantidos

- `GHSA-qwww-vcr4-c8h2` em React Router 7.18.2: superfície RSC não usada, aceitação temporária e gate
  com expiração em 15/08/2026;
- Pydantic Core 2.47 não foi aplicado isoladamente porque Pydantic 2.13.4 exige 2.46.4;
- catálogo/rulesets, validação clínica, QMS/regulação, LGPD institucional, pentest, DLP, egress de
  infraestrutura, readers de tela/usabilidade e interoperabilidade oficial são externos;
- branch protection e disponibilidade de runners são controles do GitHub, não do código local.

## Publicação condicionada

O primeiro push só ocorre com worktree limpo e `origin/main` ainda no baseline conhecido. CI,
Security e `release-readiness` precisam concluir com sucesso no SHA final. Somente então a tag anotada
`v0.8.7` e a GitHub Release são criadas. PRs Dependabot #10–#25 são comentados e encerrados depois da
publicação; nenhum é mesclado ou cherry-picked.

Este relatório é evidência de engenharia, não validação para atendimento real.
